# App Store Connect 文案规范

本文件在 `app-store-connect-copywriting`（撰写简体中文文案）和 `app-store-connect-localization`（翻译成 39 个语种）两个 skill 里各有一份，内容完全相同，`scripts/asc_check.py` 也一样。两个 skill 按同一份规范工作，前者的产出可以直接交给后者翻译。修改时两边一起改，可以用 `diff` 核对。

## 1. 字段与字符上限

| 字段 | ASC 英文名 | 上限 | 说明 |
| --- | --- | --- | --- |
| 推广文本 | Promotional Text | 170 字符 | 显示在产品页描述最上方，随时可以修改，不需要送审 |
| 此版本的新增内容 | What's New in This Version | 4000 字符 | 随新版本提交，显示在产品页的版本更新区域 |

上限是 ASC 的硬性校验，超出就无法保存，也就无法提交。语言模型数不准字符，所以长度一律用 `scripts/asc_check.py` 实测（`<skill>` 指 skill 所在目录）：

- `python3 <skill>/scripts/asc_check.py count [文本文件] [--limit N]`：统计一段纯文本，省略文件名时读标准输入。
- `python3 <skill>/scripts/asc_check.py check <文件.md> [--allow-subset]`：校验按第 7 节写成的文件，详见各 skill 的说明。

脚本按最严格的口径计数（UTF-16 码元，换行计 2），它判定通过的文本在 ASC 里一定放得下。

## 2. 「此版本的新增内容」格式

写成纯文本（ASC 不渲染 Markdown），结构固定如下：

```text
<摘要行：一句话概括本版本>

<小节标题>
• <条目>
• <条目>

<小节标题>
• <条目>
```

- **摘要行**：一句话说清本版本最重要的变化。App Store 只显示新增内容的前几行，点「更多」才展开其余部分，所以第一行要能独立传达重点。只有一两条改动的小版本可以省略摘要行，直接从小节开始。
- **小节**：固定顺序为 新增 → 优化 → 修复 → 性能 → 安全 → 移除，只写有内容的小节。标题单独占一行，不加冒号或符号；简体中文就用这六个词，其他语种用 localization skill 的 `references/locales.md` 中的对照词。各小节放什么：

  | 小节 | 内容 |
  | --- | --- |
  | 新增 | 以前没有的功能、选项、格式、语言等 |
  | 优化 | 已有功能的行为、界面、交互或默认值的改变 |
  | 修复 | 错误、异常、显示问题的修正 |
  | 性能 | 速度、内存、耗电、流畅度的提升 |
  | 安全 | 与数据安全、隐私、防止误删等相关的改动 |
  | 移除 | 被删掉或不再支持的功能、选项 |

- **条目**：以 `• `（U+2022 加一个空格）开头，一条一段，条目内不换行；用完整的句子，以句末标点结尾；同一小节内句式一致。简体中文的句式见第 5 节。
- **付费功能**：需要付费解锁的功能，在该条末尾用括号注明，叫法沿用 App 自己的（如「（需 Pro 解锁）」）。
- **空行**：摘要行与第一个小节之间、小节与小节之间各空一行；小节标题与条目之间、条目与条目之间不空行。
- 不出现 Markdown 标记（`#`、`**`、`- `）、版本号或日期。

## 3. 内容取舍

- 只写用户能感知到的变化。模块名、类名、代码重构、测试、CI、构建脚本、依赖升级、数据库版本等内部信息不写；如果它带来了用户能感知的效果（更快、更稳、某个问题消失），只写这个效果。
- 不编造源材料里没有的功能、数字、对比或承诺。
- 同一功能的多处改动合成一条，按用户看到的结果来写，不按提交或代码模块拆分。
- 界面文字（菜单项、按钮、设置项名称）用该语言的引号引用（简体中文用「」），照抄 App 在该语言下实际显示的字符串。App 界面不支持该语言时，用户看到的是别的语言（通常是英语），自行翻译出来的菜单名在 App 里找不到：这时优先直接描述功能、不加引号；必须指明具体位置时，引用 App 实际显示的原文。
- Apple 的系统名词（废纸篓、程序坞、访达、旁白等）用 Apple 在该语言的官方译名。

## 4. 长度预算与压缩

文案通常还要翻译成 39 个语种。欧洲语言的字符数一般是英文的 1.2–1.4 倍，英文约是中文的 3 倍、日文的 2 倍。源语言版本（下称母版）按下表控制，翻译后最长的语种也能放进上限：

| 母版语言 | 此版本的新增内容 | 推广文本 |
| --- | --- | --- |
| 简体中文 / 繁体中文 | 约 900 | 约 60 |
| 日语 / 韩语 | 约 1500 | 约 90 |
| 英语等拉丁字母语言 | 约 2800 | 约 120 |

单位是 ASC 计数的字符。推广文本翻译时会按各语言重写，这里的预算是为了让各语言都能装下同样的信息。

超出预算时按以下顺序压缩，越靠前越优先：

1. 删掉内部信息和重复表述。
2. 每条只留"改了什么 + 对用户有什么用"，删去实现细节、边界条件和长串枚举。
3. 合并同类的小条目（比如几处菜单显示问题合成一条）。
4. 仍然超出时，把次要的修复合并成最后一条概括性的条目（如「修复了若干界面显示问题。」）。

压缩后在汇报里告诉用户删减了什么。

## 5. 简体中文写法

- 新增：以「新增」开头，或直接描述新出现的东西（「缩略图左上角显示……」）。
- 优化：描述改动后的行为（「……改为……」）；差异不明显时用「原先……现在……」说明。
- 修复：写成「修复……的问题。」，描述用户遇到的现象，而不是代码层面的原因。
- 性能：说明哪里更快、更省，或不再卡顿。
- 安全：说明保护了什么、避免了什么风险。
- 移除：写成「移除……」，有替代做法时一并说明。
- 中文与英文、数字之间加空格（macOS 26、按 P 收藏）；斜杠两侧加空格（收藏 / 拒绝）；标点用全角；界面文字用「」；每条以句号结尾。
- 付费功能标注「（需 Pro 解锁）」，Pro 换成 App 自己的叫法。
- 语气平实、具体、以用户为中心，少用感叹号和「超强」「极致」「全新升级」之类的空泛形容词。

## 6. 「推广文本」写法

- 一到两句，突出本版本最大的亮点或 App 的核心价值；App 名已经在标题里，不必重复。
- 170 是硬上限，母版按第 4 节的预算写。翻译到其他语言时按目标语言重新创作，而不是逐字翻译：长度不够就换一种更紧凑的说法保留核心信息，而不是删到半截。
- 不写具体价格和货币（各地区价格不同），不写源材料里没有的限时优惠、排名或"最好"之类无法证实的说法，不提其他平台，不堆砌关键词。
- 源材料没有 emoji 就不加；emoji 按 2 个字符计。

## 7. 输出文件

**位置**：用户指定了路径就照办。否则看当前目录是否在 git 仓库里（`git rev-parse --show-toplevel`）：不在，写到当前目录；在，写到仓库根目录的上一级。ASC 文案以 ASC 为准，不需要进版本库，放到仓库外可以避免误提交。同名文件已存在时，除非用户要求覆盖或更新它，否则在文件名后加 `-2`、`-3`。文件名见各 skill 的说明。

**结构**：最前面是一级标题和元信息；之后每个语种一个二级标题，名称一字不改地使用 ASC 中文界面的语种名（如「简体中文」「英语（美国）」，校验脚本按名称识别）；每个语种下依次是「推广文本」「此版本的新增内容」两个三级标题，只有其中一项时只写那一项。每段文案放进 ```` ```text ```` 代码块：ASC 只接受纯文本，放在代码块里，Markdown 预览就不会把它渲染成列表或标题，用户可以原样复制。

````markdown
# App Store Connect 文案

- App：Photo Viewer 2.1.0
- 生成日期：2026-09-27
- 字符上限：推广文本 ≤ 170，此版本的新增内容 ≤ 4000

## 简体中文

### 推广文本

```text
（推广文本）
```

### 此版本的新增内容

```text
（此版本的新增内容）
```
````

多语种文件按语种顺序重复二级标题部分。元信息可以按需增减（如变更来源、源语言），不影响校验。

## 8. 示例

一个看图 App 的小版本，按本规范写出的简体中文、英语（美国）、日语「此版本的新增内容」：

简体中文

```text
新增 AVIF、JPEG XL 与 HEIF 图片浏览，并新增日语界面。

新增
• 新增 AVIF、JPEG XL（.jxl）与 HEIF（.heif）图片浏览，支持目录扫描、排序、缩略图、快速预览、EXIF 查看，以及裁剪或旋转后导出副本；这些格式暂不支持覆盖原图，也不能作为导出格式。
• 新增日语界面，可在设置中选择「日本語」；系统语言为日语时，选择跟随系统即可自动使用日语。

优化
• EXIF 面板中 .tif 文件的格式统一显示为 TIFF。
• 语言选项在任何界面语言下都以各自的母语显示（English / 简体中文 / 日本語），方便切换。

修复
• 修复英文界面下，设置「关于」页底部的评价提示被截断为单行省略号的问题。
```

英语（美国）

```text
Added browsing for AVIF, JPEG XL, and HEIF images, along with a Japanese interface.

Added
• Added browsing for AVIF, JPEG XL (.jxl), and HEIF (.heif) images, including folder scanning, sorting, thumbnails, Quick Preview, EXIF, and exporting a copy after cropping or rotating. These formats can't yet be overwritten in place or chosen as export formats.
• Added a Japanese interface. Choose "日本語" in Settings, or keep Follow System to use Japanese automatically when your Mac is set to Japanese.

Changed
• The EXIF panel now shows the format of .tif files as TIFF.
• Language options now always appear in their own language (English / 简体中文 / 日本語), whatever interface language is active.

Fixed
• Fixed an issue where the rating hint at the bottom of the About settings page was truncated to a single line in English.
```

日语

```text
AVIF、JPEG XL、HEIF画像の閲覧に対応し、日本語インターフェースを追加しました。

追加
• 追加：AVIF、JPEG XL（.jxl）、HEIF（.heif）画像の閲覧に対応しました。フォルダのスキャン、並べ替え、サムネイル、クイックプレビュー、EXIFの表示、切り抜きや回転後のコピーの書き出しに対応します。これらの形式は現時点では元画像の上書きや書き出し形式には対応していません。
• 追加：日本語インターフェースを追加しました。設定で「日本語」を選べるほか、「システムに従う」を選択している場合は、Macの言語が日本語であれば自動的に日本語で表示されます。

変更
• 変更：EXIFパネルで.tifファイルの形式をTIFFと表示するように統一しました。
• 変更：言語の選択肢を、表示言語にかかわらずそれぞれの言語名（English / 简体中文 / 日本語）で表示するようにしました。

修正
• 修正：英語表示で、設定の「情報」ページ下部にある評価の案内が1行に省略されて表示される問題を修正しました。
```
